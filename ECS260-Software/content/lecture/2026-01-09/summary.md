# ECS260 SOFTWARE - Team Communication and Meeting Best Practices

## Team Communication

- Communicate often; visibility leads to more contributions and inner‑circle invites
- Lack of communication can hide good work, even if code changes are solid
- Conflicts arise when team members assume they know everything
- Separate personal vs. professional channels (e.g., Slack, email) for clarity
- Set meeting agenda, allocate 5 min for action items, recap accomplishments

## Formulating Research Questions

- Research questions should be broader than precise hypotheses at first
- Avoid overly specific questions; start broad, then narrow down iteratively
- Example: “Is a fisheye file navigator more efficient than traditional view?”
- Validate whether efficiency is a real issue before diving deeper
- Iterative refinement with the team improves relevance and feasibility

## Efficiency & File Navigation Study (Jane’s Idea)

- Goal: assess if a fisheye lens view speeds up file browsing
- First step: measure baseline browsing time and steps taken
- Determine if users perceive efficiency gains as valuable
- Consider descriptive stats (frequency, distribution) before deeper analysis
- Compare against traditional navigation to highlight differences

## UML Diagram Usage Study (Joe’s Idea)

- Explore how widely UML diagrams are used as collaborative design artifacts
- Break the broad question into: (1) adoption rates, (2) contexts of use
- Gather data on tool usage, possibly via surveys or repository mining
- Use findings to inform whether a new tool or methodology is needed

## Literature Review & Sources

- Start with Google Scholar; expand via citation chaining (“onion” method)
- Complement with “Papers with Code” for ready‑made implementations
- Balance recent papers with seminal older work to avoid missing key results
- Identify a clear hook (why the problem matters) and a gap (what’s missing)

## Practical Tools & Workflow

- Use version‑control platforms (GitHub) to avoid reinventing existing code
- Leverage open‑source repositories and code‑with‑paper resources
- Keep personal and project communications distinct for easier tracking
- Schedule meetings promptly; aim for consistent start times (e.g., the 12th)

## General Advice for Researchers

- Treat communication as a core research skill, not an afterthought
- Iterate on research questions, methods, and analysis with peer feedback
- Document assumptions; test them early to prevent costly pivots later
- Aim for a balanced mix of descriptive, correlational, and tool‑building work.
